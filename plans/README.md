## Findings considered and rejected

Recorded so a later audit does not re-open them:

- **`bash` can leave the workspace / receives full `process.env`** — deliberate
  and documented design (ADR 0001, ADR 0003, `project-overview.md` §6.4). Not a
  finding.
- **Gemini API key in the URL query string** — Google's documented API shape; no
  project-side logging of request URLs exists.
- **`webfetch` follows redirects to arbitrary hosts** — equivalent capability is
  already available through `bash` (curl), which the ADRs treat as the
  unrestricted boundary.
- **`read` can read `.env` files** — expected for a coding agent. The real,
  still-open issue in that area is that `src/security/redaction.ts` is never
  called (dead code), which is not worth a plan on its own.
- **`RWLock` abort-listener leak / `MaxListenersExceededWarning` at >10 lock
  acquisitions per signal** — real but low impact (signals are per-turn, and the
  warning is cosmetic); noted in plan 002's maintenance section instead.
- **`finishReason` is ignored, so a token-limit truncation is presented as a
  complete answer** — confirmed real, deferred: needs a product decision about
  how much to surface in the TUI, and plan 007 already owns the TUI's status/event
  surface.
- **`runtime.*` limits configured in `config.json` are never passed to
  `AgentRuntime`** (so `maxIterations`, `maxBashTimeMs`, etc. are no-ops) —
  confirmed real and high-impact, but out of the selected scope; it is a
  one-block change in `src/cli/main.ts` and should be picked up with plan 007 or
  as its own P1.
- **Dead placeholder modules** (`src/cli/commands.ts`, `src/cli/renderer.ts`,
  `src/cli/approvals.ts`, `src/context/compaction.ts`) — plan 007 replaces the
  first three with real implementations; `src/context/compaction.ts` remains
  unused and is left for a cleanup pass.
- **No CI workflow and no tests for sessions/context/providers/skills** — plans
  004-006 add session/context tests; a CI workflow is not plotted because it
  needs a host decision (GitHub Actions assumed, but no `.github/` exists yet).
- **Injected/corrupted transcript text at the end of `src/sessions/store.ts`** —
  a real repository-integrity issue (literal `<|end|><|start|>write to=assistant…`
  fragments committed inside a comment). No plan was requested for it; it is a
  one-line deletion plus an optional CI grep and is noted here so it is not lost.
- **README links `./LICENSE`, which does not exist** — real but trivial; add the
  MIT text and a `license` field to `package.json` in any cleanup pass.
